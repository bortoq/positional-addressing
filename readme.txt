DEMO 2

ЭМУЛЯТОР ПРОСТРАНСТВА ПАРАЛЛЕЛЬНО АДРЕСУЕМЫХ ПОЗИЦИЙ
Текущее состояние проекта: 2026-05-23


НАЗНАЧЕНИЕ

	Demo 2 эмулирует адресное пространство битовых позиций.
	Основная операция пространства - параллельное копирование интервалов.
	Адресация выполняется через сортирующую сеть и сравнение индексных полей.

	Текущая активная версия vm1 реализует двухтактную адресацию:

		такт 1: i1/f1 - создание и разметка интервалов;
		такт 2: i2/f2 - транспозиция интервалов и перенос значений.

	Третий такт в активном vm1 отсутствует.


СОСТАВ ПРОЕКТА

	vm1.c
		эмулятор пространства и двухтактной адресации.

	vm1.h
		определения machine, subspace, network fabric и констант vm1.

	sort.c
		старый совместимый генератор сортирующей сети Батчера odd-even merge.
		Используется для текущего полного SPACE_SIZE = 0xfff0, потому что
		генерирует сеть ровно под размер пространства vm1.

	sort2.c
		генератор блочной сортирующей сети: рекурсивный odd-even mergesort
		с оптимальной базовой сетью на 16 входов. Этот файл важен для
		дальнейшей двухтактной и аппаратной реализации, потому что ближе
		к стабильной/блочной сети и уменьшению локальной сложности.

	space.h
		минимальные настройки генератора sort.c.

	sorter.txt
		сгенерированная текстовая сеть для текущего полного SPACE_SIZE.

	demo2.readme.rus.txt
		этот документ.


СБОРКА

	Текущий полный режим:

		cc -Wall -Wextra -std=c11 -O2 sort.c -o sort
		cc -Wall -Wextra -std=c11 -O2 vm1.c -o vm1
		./sort bld > sorter.txt
		./vm1 sorter.txt < input.bin > output.bin

	Проверка генератора sort2:

		cc -Wall -Wextra -std=c11 -O2 sort2.c -o sort2
		./sort2 65536 > sorter2_65536.txt

	Важно: текущий vm1 использует SPACE_SIZE = 0xfff0, то есть 65,520
	позиций. Поэтому сеть sort2 по умолчанию на 65,536 позиций нельзя
	подавать в текущий vm1 без слоя трансляции/guard cells или изменения
	размера пространства.


УСТРОЙСТВО VM1

	Главная структура - machine.

	Она содержит:

		space
			упакованные биты адресного пространства.

		subspace
			логическое состояние каждой позиции.

		fabric
			сортирующую сеть, загруженную из sorter.txt.

	Сортирующая сеть больше не хранится внутри каждой позиции.
	В старой конструкции у позиции были link[] и link0[].
	В текущей конструкции сеть вынесена в отдельный объект fabric:

		fabric.layers[l].pairs[p].a
		fabric.layers[l].pairs[p].b

	Это ближе к аппаратной реализации, где сеть должна быть отдельным ROM
	или генератором адресов, а не частью состояния каждой позиции.


СОСТОЯНИЕ ПОЗИЦИИ

	Каждая позиция subspace содержит:

		value
			бит значения.

		active
			признак участия позиции в копировании текущего такта.

		role
			роль интервала: источник или назначение.

		key
			адресный ключ:

				low
					нижняя граница интервала;

				high
					верхняя граница интервала;

				partner
					нижняя граница сопряженного интервала;

				sort
					текущий сортируемый индекс;

				origin
					постоянный индекс позиции.

	Поля старого вида low/high/mark/swap/index свернуты в key.
	Поля copy и way заменены на active и role.


ИНИЦИАЛИЗАЦИЯ

	При запуске vm1:

	1. открывает файл сортирующей сети;
	2. читает пары индексов;
	3. разбивает пары на слои по повторному появлению позиции в слое;
	4. сохраняет сеть в fabric;
	5. присваивает каждой позиции постоянный key.origin;
	6. записывает в начало space встроенный loader, если он помещается;
	7. записывает echo после области процессора, если он помещается;
	8. выполняет один вычислительный цикл без обслуживания каналов, чтобы
	   loader успел загрузить echo в область процессора;
	9. начинает цикл каналов и вычисления.

	Каналы:

		CHANNEL_IN  = SPACE_SIZE / CHAR_BIT - 1
		CHANNEL_OUT = SPACE_SIZE / CHAR_BIT - 2

	За один цикл vm1 читает один байт из stdin в CHANNEL_IN и выполняет
	два такта адресации. Программа echo имеет задержку на один цикл:
	первый CHANNEL_OUT после первого чтения еще содержит начальное
	значение, а введенный байт появляется на выходе после следующего
	вычисления.

	Чтобы первый введенный байт не отбрасывался, эмулятор обслуживает
	выход как однобайтный конвейер:

		- первый готовый CHANNEL_OUT не пишется в stdout;
		- начиная со второго вычисления пишется предыдущий готовый байт;
		- после EOF выполняются два вычислительных цикла без чтения,
		  затем пишется последний готовый байт.

	EOF входа завершает работу эмулятора. Это внешнее отладочное условие
	завершения.


ДВУХТАКТНАЯ АДРЕСАЦИЯ

	Вычислительный цикл vm1:

		один раз до чтения канала:
			выполнить такт 1;
			выполнить такт 2;

		while(channel_read(vm1) == 0)
			выполнить такт 1;
			выполнить такт 2;
			если выход уже прогрет, channel_write(vm1);

		после EOF:
			если выход прогрет:
				два раза выполнить:
					такт 1;
					такт 2;
				channel_write(vm1);

	Такт 1:

		i1()
			- переносит обработанные значения из subspace обратно в space;
			- читает значения space в subspace;
			- очищает active и role;
			- восстанавливает key.sort из key.origin;
			- читает из области процессора инструкции-интервалы;
			- создает начальные записи для dst и src сторон копирования.

		f1()
			- проходит по всем слоям fabric;
			- для каждой пары позиций распространяет атрибуты интервала;
			- заполняет key.sort значением сопряженного интервала там,
			  где позиция попадает внутрь копируемого интервала.

	Такт 2:

		i2()
			- записывает key.origin в key.partner.

		f2()
			- проходит по той же сети fabric;
			- сравнивает key.sort у пары позиций;
			- при необходимости транспонирует key.sort и key.partner;
			- переносит value в соответствии с role.

	Корректность одновременных копирований требует, чтобы интервалы одного
	такта были согласованы. vm1 не должен решать эту задачу внешними
	проверками: согласование должно выполняться программной логикой внутри
	самого пространства.


СОРТИРУЮЩИЕ СЕТИ

	sort.c

		Генерирует сеть Батчера odd-even merge для SPACE_SIZE из space.h.
		Это текущий совместимый генератор для vm1.

		Текстовый формат:

			0 32768
			1 32769
			2 32770

		Одна строка - одна пара позиций.

		Текущий sorter.txt:

			SPACE_SIZE: 65,520
			INDEX_SIZE: 16
			слоев: 136
			пар: 3,997,039
			максимум пар в слое: 32,760
			размер файла: около 45 MiB

	sort2.c

		Генерирует блочную сеть для размеров, кратных степени двойки,
		начиная с 16. Внутри используется оптимальная базовая сеть на
		16 входов и рекурсивный merge.

		sort2 важен для следующего шага проекта:

			- перехода к устойчивой сети для строгой двухтактной схемы;
			- уменьшения локальной сложности;
			- аппаратной реализации через блоки;
			- отказа от плоской сети полного пространства.

		Проблема совместимости:

			текущий vm1 использует SPACE_SIZE = 0xfff0, чтобы закрыть
			крайние адресные позиции. sort2 по умолчанию строит сеть
			на 65,536 позиций. Поэтому для прямого использования sort2
			нужен один из следующих шагов:

				1. вернуть SPACE_SIZE = 65,536 и добавить guard cells;
				2. добавить слой трансляции адресов;
				3. научить vm1 игнорировать/экранировать крайние позиции;
				4. адаптировать sort2 под рабочее множество 65,520.


ОЦЕНКА АППАРАТНЫХ ЗАТРАТ ТЕКУЩЕГО VM1

	Оценка относится к текущей структуре vm1, а не к оптимизированной
	ASIC/FPGA реализации.

	Используются прежние приближения:

		1 бит памяти: 6 транзисторов;
		1 бит компаратора ">": 8 транзисторов.

	Полный режим:

		SPACE_SIZE = 65,520
		INDEX_SIZE = 16
		слоев сети = 136
		пар сети = 3,997,039
		максимум пар в слое = 32,760

	Память состояния позиции:

		value  = 1 бит
		active = 1 бит
		role   = 1 бит
		key    = 5 * INDEX_SIZE = 80 бит

		Итого на позицию:

			1 + 1 + 1 + 80 = 83 бита.

	Память subspace:

		65,520 * 83 = 5,438,160 бит.

	Память space:

		65,520 бит.

	ROM сети:

		3,997,039 пар * 2 индекса * 16 бит =
		127,905,248 бит.

	Итого хранимых бит без служебных накладных расходов:

		5,438,160 + 65,520 + 127,905,248 =
		133,408,928 бит.

	6T-оценка памяти:

		133,408,928 * 6 =
		800,453,568 транзисторов.

	Компараторная логика для полностью параллельного самого широкого слоя:

		f1 содержит примерно 10 сравнений 16-битных индексов на пару.

			10 * 16 * 8 = 1,280 транзисторов на pair-unit.

			32,760 * 1,280 =
			41,932,800 транзисторов для самого широкого слоя.

		f2 содержит одно сравнение 16-битного key.sort на пару.

			16 * 8 = 128 транзисторов на pair-unit.

			32,760 * 128 =
			4,193,280 транзисторов для самого широкого слоя.

	Вывод:

		В прямой плоской аппаратной реализации главный расход - хранение
		сети. ROM сети равен 127,905,248 бит, то есть примерно 15.25 MiB.
		Это примерно в 23.5 раза больше, чем память состояния subspace.


АППАРАТНАЯ РЕАЛИЗАЦИЯ

	vm1.c нельзя буквально переводить в Verilog. C-код является
	поведенческой спецификацией.

	Практическая аппаратная структура:

		top
			соединяет control, network_rom, subspace_ram, datapath и io.

		control FSM
			заменяет циклы C. Управляет состояниями:

				IDLE
				INIT
				CHANNEL
				STAGE1_PREP
				STAGE1_RUN
				STAGE2_PREP
				STAGE2_RUN
				DONE_OR_REPEAT

		network_rom
			хранит пары сети (a,b) и границы слоев.
			В полном плоском варианте это 3,997,039 пар.
			Для аппаратной реализации желательно не хранить такую сеть
			полностью, а генерировать или сжимать ее.

		subspace_ram
			хранит value, active, role и key.
			Для полного режима это 83 бита на позицию.

		space_mem
			хранит упакованные биты пространства.
			Может быть объединена с value только после изменения протокола
			инициализации и writeback.

		stage1 datapath
			реализует f1.

		stage2 datapath
			реализует f2.

		io
			заменяет stdin/stdout и явно обрабатывает end-of-stream.

	Рекомендуемый путь:

		1. не начинать с полного пространства;
		2. сначала сделать малую аппаратную модель на степени двойки;
		3. использовать sort2 как основу блочной сети;
		4. проверить stage1/stage2 против C-эмулятора;
		5. затем переходить к тайлам и merge-уровням;
		6. для полного пространства не использовать плоский ROM сети.

	Блочное направление:

		- локальные блоки по 16 или 256 позиций;
		- локальная сеть внутри блока;
		- merge-сеть между блоками;
		- возможная конвейеризация уровней merge.

	Это главный путь к уменьшению ROM, проводов и задержек.
