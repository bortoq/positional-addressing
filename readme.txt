НАЗНАЧЕНИЕ

	Demo 2 эмулирует адресное пространство с позиционной адресацией.
	Адресуемое значение в текущей модели - бит.
	Основная операция пространства - параллельное копирование интервалов.
	Адресация выполняется через сортирующую сеть и сравнение индексных полей.

	Текущая активная версия vm1 реализует двухтактную адресацию:

		такт 1: stage1_init/stage1_pair - создание и разметка интервалов;
		такт 2: stage2_init/stage2_pair - транспозиция интервалов и перенос значений.


СОСТАВ ПРОЕКТА

	vm1.c
		эмулятор адресного пространства и двухтактной адресации.

	vm1.h
		определения machine, subspace, network fabric и констант vm1.

	sort2.c
		генератор сортирующей сети.
		Строит сеть для ближайшей степени двойки и печатает только пары,
		попадающие в диапазон рабочего множества адресного пространства.

	sorter.txt
		сгенерированная текстовая сеть для текущего SPACE_SIZE.

	readme.txt
		этот документ.


СБОРКА И ЗАПУСК

	Сборка:

		cc -Wall -Wextra -std=c11 -O2 sort2.c -o sort2
		cc -Wall -Wextra -std=c11 -O2 vm1.c -o vm1

	Генерация сети для текущего SPACE_SIZE (65,520):

		./sort2 65520 > sorter.txt

	Запуск эмулятора:

		./vm1 sorter.txt < input.bin > output.bin

	Важно:

		vm1 ожидает, что все индексы в sorter.txt меньше SPACE_SIZE.
	Программа sort2 гарантирует это при вызове ./sort2 SPACE_SIZE.


УСТРОЙСТВО VM1

	Главная структура - machine.

	Она содержит:

		space
			упакованные биты адресного пространства.

		subspace
			логическое состояние каждой позиции.

		fabric
			сортирующую сеть, загруженную из sorter.txt.

	Сеть хранится отдельно от состояния позиции:

		fabric.layers[l].pairs[p].a
		fabric.layers[l].pairs[p].b

	Это соответствует аппаратному разделению:
	хранение сети отдельно от состояния позиции.


СОСТОЯНИЕ ПОЗИЦИИ

	Каждая позиция subspace содержит:

		value
			бит значения.

		active
			признак участия позиции в копировании текущего такта.

		role
			роль интервала: источник или назначение.

		key
			адресный ключ:

				low
					нижняя граница интервала;

				high
					верхняя граница интервала;

				partner
					нижняя граница сопряженного интервала;

				sort
					текущий сортируемый индекс;

				origin
					постоянный индекс позиции.


ИНИЦИАЛИЗАЦИЯ И ОГРАНИЧЕНИЯ

	При запуске vm1:

	1. открывает файл сортирующей сети;
	2. читает пары индексов;
	3. разбивает пары на слои по повторному появлению позиции в слое;
	4. сохраняет сеть в fabric;
	5. присваивает каждой позиции постоянный key.origin.

	Эмулятор записывает встроенный загрузчик в начало address space.
	Загрузчик занимает одну инструкцию: 8 байт (4 слова типа idx).
	Копирование выполняется только если размер массива space не меньше
	размера одной инструкции. В текущей конфигурации это условие выполняется.

	Если при изменении конфигурации условие не выполняется, запись загрузчика
	не производится. Тогда область процессора остается с нулевыми значениями:
	цикл вычислений продолжает выполняться, но инструкции копирования не
	активируются до явной записи программы в address space.

	Каналы:

		CHANNEL_IN  = SPACE_SIZE / CHAR_BIT - 1
		CHANNEL_OUT = SPACE_SIZE / CHAR_BIT - 2

	За один цикл vm1:

		- читает один байт из stdin в CHANNEL_IN;
		- выполняет оба такта адресации;
		- пишет один байт из CHANNEL_OUT в stdout.

	EOF входа завершает работу эмулятора.
	Основное ограничение времени работы задается константой LIFE в vm1.h.


ДВУХТАКТНАЯ АДРЕСАЦИЯ

	Вычислительный цикл vm1:

		while(life-- && channel_read(vm1) == 0)
			stage1_init(vm1);
			stage1_pair(...) по всем парам сети;
			stage2_init(vm1);
			stage2_pair(...) по всем парам сети;
			channel_write(vm1);

	Такт 1:

		stage1_init()
			- переносит обработанные значения из subspace обратно в space;
			- читает значения space в subspace;
			- очищает active и role;
			- восстанавливает key.sort из key.origin;
			- читает из области процессора инструкции-интервалы;
			- создает начальные записи для dst и src сторон копирования.

		stage1_pair()
			- для каждой пары позиций распространяет атрибуты интервала;
			- заполняет key.sort значением сопряженного интервала там,
			  где позиция попадает внутрь копируемого интервала.

	Такт 2:

		stage2_init()
			- записывает key.origin в key.partner.

		stage2_pair()
			- сравнивает key.sort у пары позиций;
			- при необходимости транспонирует key.sort и key.partner;
			- переносит value в соответствии с role.

	Термин "stage" в коде означает "такт адресации".
	Термин "cycle" означает полный вычислительный цикл:
	stage 1 + stage 2.


СОРТИРУЮЩАЯ СЕТЬ (sort2)

	sort2 генерирует сеть алгоритма odd-even mergesort:

	1. выбирает ближайший размер степени двойки >= SPACE_SIZE;
	2. строит полную сеть для этого размера;
	3. печатает только те пары (a,b), где a < SPACE_SIZE и b < SPACE_SIZE.

	Текстовый формат sorter.txt:

		0 32768
		1 32769
		2 32770

	Одна строка - одна пара компараторов.

	Параметры текущего sorter.txt:

		число пар: 3,984,771
		число слоёв: 136
		максимум пар в слое: 32,760

	Эта схема устраняет рассинхронизацию между размером сети и размером
	fabric в vm1.


ОЦЕНКА АППАРАТНЫХ ЗАТРАТ АКТУАЛЬНОГО VM1

	Оценка относится к текущей структуре vm1.
	Используются приближения:

		1 бит памяти: 6 транзисторов;
		1 бит компаратора ">": 8 транзисторов.

	Параметры текущего набора данных:

		SPACE_SIZE = 65,520
		INDEX_SIZE = 16
		максимум пар в слое <= floor(SPACE_SIZE / 2) = 32,760

	Состояние позиции:

		value  = 1 бит
		active = 1 бит
		role   = 1 бит
		key    = 5 * INDEX_SIZE = 80 бит

		Итого на позицию:

			83 бита

	Память subspace:

		65,520 * 83 = 5,438,160 бит

	Память space:

		65,520 бит

	ROM сети:

		Размер зависит от конкретного sorter.txt.
		Формула:

			pairs_total * 2 * INDEX_SIZE бит

		Где pairs_total - число строк в sorter.txt.

		Для текущего sorter.txt:

			pairs_total = 3,984,771
			ROM_bits = 3,984,771 * 2 * 16 = 127,512,672 бит

	6T-оценка памяти:

		без ROM сети:

		(5,438,160 + 65,520) * 6 =
		33,022,080 транзисторов

		с учетом ROM сети:

		(5,438,160 + 65,520 + 127,512,672) * 6 =
		798,098,112 транзисторов

	Логика сравнения для одного pair-unit:

		stage1_pair:
			до 10 сравнений 16-битных индексов
			~ 10 * 16 * 8 = 1,280 транзисторов

		stage2_pair:
			1 сравнение 16-битных индексов
			~ 16 * 8 = 128 транзисторов

	Для полностью параллельного широкого слоя:

		stage1: 32,760 * 1,280 = 41,932,800
		stage2: 32,760 *   128 =  4,193,280

	Замечание:

		Главный вклад площади в полном варианте обычно дает хранение сети.
		Точное значение определяется конкретным pairs_total в sorter.txt.


АППАРАТНАЯ РЕАЛИЗАЦИЯ

	vm1.c является поведенческой спецификацией.
	Прямая трансляция C-кода в язык описания аппаратуры не предполагается.

	Практическая структура:

		top
			соединяет control, network_rom, subspace_ram, datapath и io.

		control finite state machine (конечный автомат управления)
			заменяет циклы C. Базовые состояния:
				IDLE
				CHANNEL_READ
				STAGE1_INIT
				STAGE1_RUN
				STAGE2_INIT
				STAGE2_RUN
				CHANNEL_WRITE
				DONE_OR_REPEAT

		network_rom (постоянная память сети)
			хранит пары сети (a,b) и границы слоев.

		subspace_ram (оперативная память состояния позиций)
			хранит value, active, role и key.

		space_mem
			хранит упакованные биты address space.

		stage1 datapath (тракт обработки stage 1)
			реализует stage1_pair.

		stage2 datapath (тракт обработки stage 2)
			реализует stage2_pair.

		io (ввод-вывод)
			реализует CHANNEL_IN/CHANNEL_OUT и конец входного потока.

	Рекомендуемый путь:

		1. сначала синтезировать малую модель;
		2. проверить stage1/stage2 против C-эмулятора;
		3. добавить поуровневую конвейеризацию;
		4. оптимизировать хранение/генерацию сети.


ТЕСТИРОВАНИЕ

	Тесты не являются частью логики исполнения vm1.
	Тестовые сценарии должны задаваться как данные адресного пространства
	(программа в processor area + входной поток в CHANNEL_IN).

	Рекомендуемый подход:

		1. подготовить образ address space с программой интервалов;
		2. подать входной поток;
		3. сравнить выход CHANNEL_OUT с ожидаемым потоком.


ГЛОССАРИЙ

	address space
		Адресное пространство vm1. В коде это упакованный массив `space`.

	position
		Одна адресуемая позиция внутри address space.

	subspace
		Логическое состояние всех позиций (value, active, role, key).

	key
		Лексикографический адресный ключ позиции: low/high/partner/sort/origin.

	interval
		Полуинтервал копирования, заданный ограничителями low/high.

	sorting network
		Сеть пар компараторов, организованная по слоям (`fabric.layers`).

	layer
		Набор пар сети, которые можно применять параллельно.

	pair
		Одна пара индексов (a,b) в sorting network.

	stage
		Один такт адресации. В vm1 два stage: stage 1 и stage 2.

	cycle
		Полный вычислительный цикл vm1: stage 1 + stage 2.

	stage1_init
		Подготовка stage 1: синхронизация space/subspace, сброс флагов, загрузка интервалов.

	stage1_pair
		Применение правил stage 1 к одной паре компараторов.

	stage2_init
		Подготовка stage 2: запись origin в partner.

	stage2_pair
		Применение правил stage 2 к одной паре компараторов (сравнение/обмен/перенос).

	processor area
		Область address space, где хранятся инструкции интервалов.

	channel
		Байтовый I/O-интерфейс address space: CHANNEL_IN и CHANNEL_OUT.
