# Проверка vm1 — 2026-10-18

**Программная приёмка: PASS.** Полуинтервалы и трёхфазный механизм проходят
независимый эталон копирования. Физическая приёмка аппаратных затрат остаётся
отдельной незавершённой работой: RTL и транзисторной модели пока нет.

## Причины возврата третьей фазы

Историческая реализация в `da83591^:v0/vm1.c` содержала третью фазу для
восстановления порядка исходных позиций. Её удалили при переходе к двум
фазам, полагаясь на стабильность pairwise-сети. Контрпример на четырёх
элементах доказывает, что равные ключи меняют взаимный порядок; он приведён
в [описании алгоритма](README.md#why-three-phases-were-restored).

До смены формата независимая проверка выявила также ошибки разметки и
переноса данных: отдельные копирования не выполнялись, повреждались источники
и посторонние биты. Переход одних сравнений на полуинтервалы давал 1455 ошибок
из 1793 случаев на малой сети и 72 из 78 на штатной. Возврат одной старой
функции третьей фазы эти ошибки не устранял.

Исправлено три части механизма:

- Разметка распространяет по одному дескриптору. Классификация `role/sort`
  сохраняется независимо от перемещаемого токена. Поле `value` временно
  хранит направление токена; реальные данные читаются позже из `space`.
- Перестановка переносит ключ, исходную позицию, значение и признак записи
  вместе, сохраняя целостность записи.
- Третья фаза упорядочивает биты группы назначения по исходным позициям.
  Устойчивость сети и дополнительные разряды сравниваемого ключа не требуются.

Владелец разрешил дополнительные проходы разметки без новых ячеек. На K
активных копирований приходится `2K+2` прохода по прежней сети, а не три.
Поля позиции и число позиций не расширены. Модель использует сравнение и
передачу метаданных/битов через сеть; прямого host-копирования вместо адресации нет.

Отдельно исправлен десериализатор сети: первая пара после начала нового
слоя должна заново резервировать оба провода. Старый код мог скрыто помещать
конфликтующие пары в один аппаратный слой. Теперь каждый слой малой и штатной
сети независимо проверяется на отсутствие повторного использования проводов.

Эталон независимо проверяет допустимость расписания и строит результат из
снимка всей памяти начала цикла. Он сравнивает назначения, источники,
неизменяемые позиции и процессор. Проверяются позиции 0 и S−1, соседние
диапазоны, полное копирование половин пространства, перебор размещений
одного и двух копирований в восьмибитном окне, случайные данные, все 128
слотов, повторные циклы, длины 1–127, невыровненные адреса и самомодификация.
Отдельно подтверждается распространение токена из позиции 0 во все ячейки
обеих сетей. Контрпример потери копирования до перехода сохранён в тестах.

Тестовое исключение вызова третьей фазы из исправленного движка снова
нарушает независимый эталон. Проверки не ослаблялись ради приёмки.
Старые chain/dual-сценарии нарушали непересечение src/dst и удалены;
канальные тесты теперь проверяют точные байты/длину/задержку и возвращают
ненулевой код при сбое, вместо принятия произвольного сдвига вывода.

## Воспроизведение

```sh
make clean
make check CFLAGS='-Wall -Wextra -Werror -pedantic -std=c11 -O2'
```

Санитайзеры проверяются после чистой пересборки:

```sh
make clean
ASAN_OPTIONS=detect_leaks=0 UBSAN_OPTIONS=halt_on_error=1 \
  make check CFLAGS='-Wall -Wextra -Werror -pedantic -std=c11 -O1 -g -fsanitize=address,undefined -fno-omit-frame-pointer -fno-pie -no-pie'
```

LeakSanitizer отключён: в данной среде он завершает работу с сообщением о
несовместимости с ptrace. Отсутствие утечек этим прогоном не утверждается.

Исходный дефект открытых интервалов можно повторить из текущих тестов:

```sh
make sort sorter
scratch=$(mktemp -d)
git show 8e98731:src/machine.c > "$scratch/machine-before.c"
cc -std=c11 -O2 -Isrc -DLEGACY_OPEN \
  -DVM1_MACHINE_SOURCE="\"$scratch/machine-before.c\"" \
  tests/test_addressing.c -o "$scratch/test-before"
"$scratch/test-before" sorter.txt  # ожидается сбой старой реализации
rm -rf "$scratch"
```

## Границы приёмки

Функциональный PASS относится к исполняемой модели C и указанным проверкам,
а не к исчерпывающему доказательству всех возможных программ. Старые заявления
аудита о двух фазах и стабильности сети больше не действуют; история остаётся
в Git. Формат полуинтервалов требует пересборки старых open-interval образов.

Существующий byte-channel loop/LDR1 не заменялся новым механизмом каналов.
Прямое эхо по-прежнему имеет задержку один логический цикл, EOF не сбрасывает
отложенные результаты. `examples/sort256_runtime.vm1` остаётся заглушкой.
Аппаратные ограничения, стоимость контроллера и рост переключений из-за
повторных проходов описаны в [hardware.md](hardware.md); физическая проверка
не закрывается прохождением программных тестов.
