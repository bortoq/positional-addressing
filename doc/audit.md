# Проверка vm1 — 2026-10-18

**Программная приёмка: PASS.** Новая адресация полуинтервалов использует
сортировку дескрипторов и монотонное разделение диапазонов, включая поддержку
отсутствующих проводов неполной сети. Физическая приёмка RTL остаётся открытой.

## Изменение алгоритма

Независимые входы инструкций сохранены. Вместо девяти сортировок виртуальных
записей и трёх префиксов выполняется один сортирующий проход дескрипторов,
после которого активные запросы стоят подряд по нижней границе. Butterfly
разделяет ответственность каждого дескриптора на непересекающиеся поддиапазоны.
Фазы 2/3 продолжают переносить полные записи и восстанавливать порядок битов.

Неполный размер не дополняется новыми ячейками: временные ghost-дескрипторы
используют прежние свободные поля, с двумя 8-битными границами в одном слове.
Смешанная пара проходит пять подслоёв через существующие связи. Подробности,
условия отсутствия конфликтов и доказательство упаковки — в [алгоритме](README.md).

Штатное расписание: 3*136 + 16 + 25 = **449 сетевых слоёв**, плюс пять
локальных шагов, всего **454**. При K=0/1/128 одинаковы глубина, число обращений
к парам и хеш расписания. Старый механизм требовал 3234 шага. Ровно три прохода
без дополнительных слоёв не заявляются.

|---|---|
| Machine units | 150/150 |
| Network / loader / compiler units | 43/43, 36/36, 33/33 |
| Сортировка и точное канальное эхо | PASS, 4/4 |
| Независимый эталон, N=240 | 1796 случаев, 0 ошибок |
| Независимый эталон, N=256 | 1796 случаев, 0 ошибок |

| Полный `make check` под ASan/UBSan | PASS |

Эталон строит результат из снимка начала цикла независимо от ключей движка и
сравнивает все биты памяти, включая источники, свободные позиции и процессор.
Сохранены проверки границ, соседних интервалов, всех размещений одного и двух
копирований в малом окне, случайных данных, всех слотов, NOP, повторных циклов,
длин 1–127, невыровненных диапазонов и самомодификации.

Добавлены плотные чтения/записи конца неполной сети всеми слотами, повторный
цикл после ghost-маршрутизации и восемнадцатый дескриптор, достигающий последней
позиции. Сохранён контрпример двух однобитных инструкций, который отвергает
прежний локальный трёхпроходный кандидат: 8194→8192 и 8196→8193.

Структурные тесты независимо сравнивают классификацию каждой позиции с обходом
интервалов: полный перебор двух диапазонов в 16-позиционном окне на малых сетях,
плотное заполнение хвоста всеми дескрипторами, 18-дескрипторный контрпример и
24 случайных набора с перестановкой входов. Расписание трассируется отдельно
от результата: каждый физический узел используется не более одного раза за слой,
каждая построенная связь присутствует в загруженной сети. Проверки K=0/1/max
выполняются на всех шести размерах. Для N=65520: 454 шага, 12 515 741 обращение
к парам/локальным операциям, хеш `920f2e1fc847fa59`.

Дополнительное исследование тех же структурных проверок прошло на N=1536,
2064, 4112, 8192, 16400, 49168 и 65504. Постоянные формы 1040/32784/60000
проверяют разные моменты появления ghost-записей, широкий разрыв до степени
двойки и локальную смешанную пару старшего измерения.

## Воспроизведение

```sh
make clean
make check CFLAGS='-Wall -Wextra -Werror -pedantic -std=c11 -O2'
make check-parallel-shapes
```

Полный набор под санитайзерами после чистой пересборки:

```sh
make clean
ASAN_OPTIONS=detect_leaks=0 UBSAN_OPTIONS=halt_on_error=1 \
  make check CFLAGS='-Wall -Wextra -Werror -pedantic -std=c11 -O1 -g -fsanitize=address,undefined -fno-omit-frame-pointer -fno-pie -no-pie'
```

LeakSanitizer отключён из-за несовместимости с ptrace в данной среде;
отсутствие утечек этим прогоном не утверждается.

## Границы приёмки

Программный PASS относится к модели C и указанным тестам. Он не заменяет
проверку RTL, транзисторов, контроллера, мультиплексоров, задержек и энергии.
Состояние позиции осталось прежним: пять слов и три флага, 83 логических бита;
`origin` временно изменяется при ghost-маршрутизации. Физическая оптимизация
константным проводом вместо этого слова требует отдельного пересмотра.

Существующий byte-channel loop/LDR1 не менялся: вывод отражает предыдущий
зафиксированный результат, прямое эхо имеет задержку один логический цикл,
EOF не сбрасывает отложенные данные. Старые образы с открытыми интервалами
требуют перекомпиляции. `examples/sort256_runtime.vm1` остаётся заглушкой.
