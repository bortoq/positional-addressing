# vm1 — Roadmap и контракт проекта

Версия 2.1, 2026-10-18. Текущий программный механизм использует полуинтервалы
и три фазы. Независимые функциональные проверки проходят. Физическая
реализация и её транзисторная/энергетическая приёмка остаются будущей работой.

## 1. Цель и формат

Параллельное копирование битов без арифметики над адресными ключами в механизме.

- Инструкция: `[dst_low,dst_high,src_low,src_high]`, четыре 16-битных слова.
- Полуинтервал `[low,high)`: нижняя граница включена, верхняя исключена.
- Активные src/dst равной положительной длины, все их позиции одного цикла
  попарно различны, включая src/src. Общая граница соседних диапазонов допустима.
- Равные границы src означают NOP; dst игнорируется. Генератор выдаёт
  канонический NOP с равными границами обеих сторон.
- `0 <= low <= high <= SPACE_SIZE`; конец должен помещаться в прежний `idx`.
  Штатные 65520 позиций поддерживаются; 65536 не помещаются в 16-битную границу.
- Процессор — часть памяти. Новые инструкции после копирования действуют
  со следующего логического цикла.

## 2. Архитектура

| Модуль | Файлы | Ответственность |
|---|---|---|
| Machine | `src/machine.c/.h` | Три фазы адресации, память, сеть, существующий цикл каналов |
| Network | `src/network.c` | Pairwise-сеть, фильтрация и упаковка слоёв |
| Loader | `tools/loader.c`, `src/loader.h` | LDR1 и встроенная инструкция загрузчика |
| Compile | `tools/compile.c` | copy3 → четыре слова полуинтервалов |
| Tests | `tests/*.c` | Units, сеть, точное эхо и независимый эталон копирования |

Состояние позиции не расширено: `value`, `active`, `role` и пять 16-битных
полей `{low,high,partner,sort,origin}` — 83 логических бита. Память содержит
65520 бит; процессор — до 128 инструкций (512 слов). Сеть содержит
3 997 039 пар, 136 слоёв. Равные ключи **не** гарантируют стабильный порядок.

Формат и привязки каналов пока прежние: последние два байта памяти — ввод и
вывод; опциональный префикс LDR1, затем один входной байт на цикл, `LIFE=16`.
Вывод наблюдает ранее зафиксированный результат: прямое эхо имеет задержку
один цикл, EOF не сбрасывает отложенные результаты. Переделка каналов —
отдельная задача, здесь не объявляется реализованной.

## 3. Три фазы

1. **Разметка:** зафиксировать предыдущий результат, сбросить классификацию.
   По одному распространить каждый dst/src-дескриптор по прежней сети.
   `value` временно хранит направление дескриптора; данные остаются в `space`.
   `role/sort` запоминают классификацию позиции и не перемещаются с токеном.
2. **Перестановка:** загрузить данные из `space`, установить `partner=origin`.
   Сортировать по `sort`, перемещая вместе ключ группы, исходную позицию,
   значение и признак записи.
3. **Восстановление порядка:** внутри групп назначения упорядочить значения
   по исходным позициям `partner`. Разные группы не обмениваются данными.

Для K активных копирований: `2K+2` прохода по той же сети, а не три прохода.
Владелец явно разрешил дополнительную работу внутри разметки без новых ячеек
2026-10-18. Число фаз, число проходов и число аппаратных тактов различаются.
Подробное обоснование возврата и контрпример стабильности: `doc/README.md`.

## 4. Этапы

### Этапы 0–3 — инфраструктура, сеть, машина и инструменты

- [x] Сборка, очистка, генерация сети, LDR1 с pushback для pipe.
- [x] Сеть сортирует ключи; слои не используют один провод дважды.
- [x] Исправлена повторная регистрация обоих проводов первой пары нового слоя.
- [x] Компилятор и загрузчик поддерживают полуинтервалы и позицию 0.
- [x] Защита компилятора от переполнения выполняется до сложения.

### Этап 4 — независимая проверка

- [x] Пофункционные проверки машины, сети, загрузчика и компилятора.
- [x] Проверка сортировки и точного эха с обязательным кодом ошибки при сбое.
- [x] Эталон одновременного копирования сравнивает всю память, включая src,
  нетронутые биты и процессор; проверяет допустимость входного расписания.
- [x] Малая и штатная сети: границы, соседние диапазоны, перебор размещений,
  несколько копирований, самомодификация и воспроизводимые случайные данные.
- [x] Все 128 слотов, повторные циклы, длины 1–127 и невыравненные адреса.
- [x] Слои обеих загруженных сетей проверяются на повторное использование проводов.
- [x] Тестовое отключение третьей фазы вызывает ошибки независимого эталона.
- [x] Строгая сборка и полный `make check` проходят.
- [ ] Физическое соответствие схемы модели — в этапе 6, не заменяется C-тестами.

### Этап 4.1 — переход на полуинтервалы и возврат третьей фазы

- [x] **4.1.1. Исходная семантика.** Зафиксирован воспроизводимый дефект старого
  движка до смены формата, включая повреждение источников/посторонних битов.
  Старые заявления о полной независимой проверке отозваны.
- [x] **4.1.2. Контракт границ.** `[low,high)`, одинаковые длины, NOP, границы
  пространства и непересечение всех src/dst определены в документации.
- [ ] **4.1.3. Аппаратное подтверждение.** Поля и сеть сохранены, описано
  повторное использование ячеек и сравнения `>`/`>=` одной топологии.
  Полное доказательство транзисторного бюджета и измерение энергии требуют RTL.
  Прежний запрет дополнительных проходов заменён прямым решением владельца:
  дополнительная работа разметки допустима без новых ячеек.
- [x] **4.1.4. Движок.** Возвращена третья фаза; разметка выдаёт дескрипторы
  последовательно; перестановки переносят полные записи. Историческая
  третья функция сама по себе не исправляла разметку и перенос значений.
- [x] **4.1.5. Форматы и инструменты.** Четыре слова и упаковка LDR1 сохранены;
  старые открытые диапазоны несовместимы и требуют пересборки. Автоопределения
  формата и дополнительного аппаратного декодера нет.
- [x] **4.1.6. Функциональная приёмка.** Независимый эталон проходит; исходные
  ошибки не скрыты ослаблением проверок или прямым копированием на C.
- [x] **4.1.7. Документация.** Согласованы README, алгоритм, аудит и аппаратные
  ограничения. Рост времени/переключений от повторных проходов указан явно.

## 5. Проверка и приёмка

```sh
make clean
make check CFLAGS='-Wall -Wextra -Werror -pedantic -std=c11 -O2'
make check-addressing
```

Для программной приёмки обязательны зелёные независимые тесты, строгая сборка
и санитайзеры; известные ограничения среды фиксируются в `doc/audit.md`.
Физическая приёмка имеет отдельные критерии этапа 6.
