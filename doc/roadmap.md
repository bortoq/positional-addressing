# vm1 — Roadmap и контракт проекта

Версия 2.6, 2026-10-18. Полуинтервалы и независимое чтение инструкций
реализованы в модели C. Механизм имеет две фазы: разметку и устойчивое
упорядочение данных. Сравнение исходных позиций и направленное сравнение
ключей используют один 16-битный компаратор и прежний флаг `active`.
Штатная глубина — 449 сетевых/сравнительных слоёв + 5 локальных шагов = 454,
независимо от K. C-модель быстрее трёхфазного контроля примерно на 12–15%
на измеренных нагрузках; энергия и физические затраты остаются этапом 6.

## 1. Цель и формат

Параллельное копирование битов без арифметики над адресными ключами в механизме.

- Инструкция: `[dst_low,dst_high,src_low,src_high]`, четыре 16-битных слова.
- Полуинтервал `[low,high)`: нижняя граница включена, верхняя исключена.
- Активные src/dst равной положительной длины, все их позиции одного цикла
  попарно различны, включая src/src. Общая граница соседних диапазонов допустима.
- Равные границы src означают NOP; dst игнорируется. Генератор выдаёт
  канонический NOP с равными границами обеих сторон.
- `0 <= low <= high <= SPACE_SIZE`; конец должен помещаться в прежний `idx`.
  Штатные 65520 позиций поддерживаются; 65536 не помещаются в 16-битную границу.
- Целевая глубина адресации всего такта — `O(log² N)` слоёв при параллельной
  работе ячеек, независимо от числа активных инструкций K. Фиксация числа
  слотов процессора не должна скрывать множитель K в оценке.
- Процессор — часть памяти. Новые инструкции после копирования действуют
  со следующего логического цикла.

## 2. Архитектура

| Модуль | Файлы | Ответственность |
|---|---|---|
| Machine | `src/machine.c/.h` | Две фазы адресации, память, сеть, существующий цикл каналов |
| Network | `src/network.c` | Pairwise-сеть, фильтрация и упаковка слоёв |
| Loader | `tools/loader.c`, `src/loader.h` | LDR1 и встроенная инструкция загрузчика |
| Compile | `tools/compile.c` | copy3 → четыре слова полуинтервалов |
| Tests | `tests/*.c` | Units, сеть, точное эхо и независимый эталон копирования |

Состояние позиции не расширено: `value`, `active`, `role` и пять 16-битных
полей `{low,high,partner,sort,origin}` — 83 логических бита. Память содержит
65520 бит; процессор — до 128 инструкций (512 слов). Сеть содержит
3 997 039 пар, 136 слоёв. Равные ключи **не** гарантируют стабильный порядок.

Формат и привязки каналов пока прежние: последние два байта памяти — ввод и
вывод; опциональный префикс LDR1, затем один входной байт на цикл, `LIFE=16`.
Вывод наблюдает ранее зафиксированный результат: прямое эхо имеет задержку
один цикл, EOF не сбрасывает отложенные результаты. Переделка каналов —
отдельная задача, здесь не объявляется реализованной.

## 3. Две фазы

1. **Разметка:** зафиксировать предыдущий результат, независимо прочитать
   слоты через фиксированные входы. Одним проходом сортировки расположить
   дескрипторы подряд по нижней границе. Разделить их через butterfly;
   отсутствующие провода используют прежние свободные поля и связи.
   Данные остаются в `space`, `origin` восстанавливается перед фазой 2.
2. **Устойчивое упорядочение:** загрузить данные и установить `partner=origin`.
   Для каждой пары слоя сравнить исходные позиции, сохранив результат в `active`.
   Затем сравнить ключи групп с выбранным по флагу направлением операндов и
   инверсией результата. Это даёт лексикографический порядок `(sort,partner)`
   за два строгих 16-битных сравнения и одну перестановку полной записи.
   Отдельная третья фаза больше не требуется.

Сортировка разметки занимает 136 слоёв; данные — 272 сравнительных шага,
разделение — 16, обработка отсутствующих проводов — 25, локальные шаги — 5.
Всего 454, без зависимости от активного K. Полей, позиций и связей не добавлено.
Процессор имеет 1–128 слотов; предел 256 дескрипторов нужен для упаковки
границ отсутствующего провода. Уменьшение до 318 предполагает обработку
составного сравнения за один аппаратный шаг; такая стоимость не доказана.
Владелец разрешил дополнительную работу разметки без новых ячеек 2026-10-18.
Подробное обоснование возврата и контрпример стабильности: `doc/README.md`.

## 5. Проверка и приёмка

```sh
make clean
make check CFLAGS='-Wall -Wextra -Werror -pedantic -std=c11 -O2'
make check-addressing
make check-parallel
```

Для программной приёмки обязательны зелёные независимые тесты, строгая сборка
и санитайзеры; известные ограничения среды фиксируются в `doc/audit.md`.
Физическая приёмка имеет отдельные критерии этапа 6.
